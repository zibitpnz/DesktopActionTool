# DesktopActionTool

Локальный инструмент для управления окнами, мышью и клавиатурой Windows через CLI или дополнительный MCP-сервер. Подходит для ручного запуска, сценариев автоматизации и управления рабочим столом из модели, анализирующей скриншоты. Результаты команд возвращаются в JSON; MCP также передаёт изображения PNG.

Инструмент умеет:

- фокусировать, сворачивать и изменять размер окон Windows;
- получать список окон и активное окно;
- делать скриншоты активного или выбранного окна;
- делать снимок после действия в том же вызове с настраиваемой задержкой;
- предупреждать пользователя о работе рамкой на мониторах, в том числе между командами одного сеанса;
- добавлять на скриншот кроссхэйр курсора, виртуальный прицел цели и внешнюю координатную линейку;
- получать и подсвечивать Win32/UI Automation-контролы окна;
- получать координаты курсора в системе `screen`, `window` или `client`;
- плавно перемещать мышь, двигать курсор относительно текущей позиции;
- кликать левой или правой кнопкой мыши;
- скроллить колесом мыши с задержками, пачками и джиттером;
- вводить текст через WinAPI `SendInput`, без буфера обмена;
- выполнять действия в текстовом поле: `Ctrl+A`, `Delete`, `Backspace`, `Enter`.

Основной сценарий использования: оператор или модель смотрит скриншот окна, выбирает координаты цели, перемещает курсор, подтверждает позицию новым скриншотом и только затем кликает или вводит текст. Анализ изображения и выбор следующего действия выполняются снаружи инструмента.

Точка входа CLI — `type_text.py`, MCP — `mcp_server.py`. Windows API, окна, контролы, ввод, состояние и отрисовка снимков выделены в отдельные модули. Win32/UI Automation-контролы остаются частью инструмента.

## Привязка к целевому окну

Для ввода, мыши и изменения окон обязательно выберите цель через `--window-id`, `--window-title`/`--process-name` или начните привязанный к окну сеанс. Без цели действие возвращает `TARGET_REQUIRED`. Текущее активное окно автоматически не выбирается. Команды чтения, включая `--list-windows` и `--active-window`, доступны без цели.

```powershell
python .\type_text.py --list-windows
$windowId = [int64](Read-Host "Введите id целевого окна")
python .\type_text.py --session-start --window-id $windowId
python .\type_text.py --focus-only
```

В этом сеансе следующие команды могут не указывать окно: они наследуют сохранённые HWND, PID и время создания процесса. Явный выбор другого окна возвращает `SESSION_TARGET_MISMATCH`. Закрытие или смена процесса цели блокирует действие с `WINDOW_CHANGED`. После завершения или истечения сеанса команды без цели снова запрещены. Статус и привязку можно проверить через `--session-status` в поле `session.target`.

Перед вводом и каждым новым событием мыши проверяются окно и фокус; во время действия проверяются также геометрия, DPI и видимость. Клики и прокрутка требуют, чтобы под курсором находилось целевое окно. Для наведения проверяется доступность выбранной точки, для перетаскивания и дрожания курсора при прокрутке — очередной точки движения. При потере фокуса возвращается `FOCUS_CHANGED`, при перекрытии цели — `TARGET_OCCLUDED`. Удерживаемые клавиши и кнопки освобождаются при остановке. Счётчики `completed` показывают уже отправленный ввод: повторять всю команду без проверки результата не следует.

Ввод и наведение не переводят фокус автоматически. Используйте отдельную команду `--focus-only`, когда намеренно хотите активировать выбранное окно. Если действие открыло диалог, для работы с ним завершите старый сеанс через `--session-end`, выберите диалог из нового списка окон и запустите `--session-start --window-id ...`. Автоматического перехода на диалог или на перезапущенное приложение нет. Чтение явно указанного другого окна разрешено для его осмотра.

Защита действует и при `--no-activity-frame`, и при `--no-abort-key`. Настройки отключения этих проверок нет. Старый сеанс, созданный версией без привязки, нужно завершить и начать заново с выбранным окном.

Проверка цели и отправка события являются отдельными операциями: [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) использует общий поток ввода Windows. Поэтому эти проверки уменьшают риск ошибочного ввода, но не обеспечивают абсолютную изоляцию окна в момент системного переключения фокуса. Они также не фиксируют конкретное поле внутри окна: его нужно выбирать и проверять по снимку.

## Новые возможности

Окно можно выбрать по точному заголовку и имени процесса:

```powershell
python .\type_text.py --list-windows --process-name notepad.exe
python .\type_text.py --window-title "Документ" --process-name editor.exe --focus-only
```

Имя процесса сравнивается без учёта регистра. Совместные фильтры применяются одновременно. Для действия требуется ровно одно совпадение; при неоднозначности возвращаются `WINDOW_AMBIGUOUS` и массив `candidates`. Для списка несколько совпадений допустимы. Фильтры нельзя сочетать с явным `--window-id`.

Поиск и ожидание UIA-контролов:

```powershell
python .\type_text.py --window-id $windowId --uia-list-controls --uia-name "Сохранить"
python .\type_text.py --window-id $windowId --uia-list-controls --uia-automation-id saveButton
python .\type_text.py --window-id $windowId --wait-control --uia-automation-id saveButton --timeout-s 10
```

Имя и AutomationId сравниваются точно, фильтры можно сочетать с `--uia-control-types`. Ожидание требует одного видимого, доступного элемента с непустой геометрией. Дубликаты возвращают `CONTROL_AMBIGUOUS`. По умолчанию таймаут UIA-чтения — 5 секунд, интервал повторного поиска — 100 мс (`--poll-interval-ms`). Зависший провайдер прерывается завершением служебного процесса; целевое приложение продолжает работать. В режиме `--dry-run` ожидание возвращает план без опроса.

Сочетания клавиш выполняются отдельной командой:

```powershell
python .\type_text.py --window-id $windowId --hotkey Ctrl+S --quiet
python .\type_text.py --window-id $windowId --hotkey Ctrl+Shift+Home --quiet
```

Модификаторы: `Ctrl`, `Alt`, `Shift`, `Win`. Основные клавиши: `A`–`Z`, `0`–`9`, `F1`–`F24`, `Enter`, `Tab`, `Escape`, `Space`, `Backspace`, `Delete`, `Insert`, `Home`, `End`, `PageUp`, `PageDown`, `Left`, `Right`, `Up`, `Down`. Регистр имён не важен. Модификаторы нажимаются в указанном здесь порядке, отпускаются в обратном. `--hotkey` нельзя совмещать с вводом текста или другими клавиатурными командами. Перед `Enter` отдельно проверьте текст на снимке.

После полного цикла проверки цели и курсора можно выполнить двойной клик:

```powershell
python .\type_text.py --window-id $windowId --double-click left
```

Оба клика расходуют одну проверку. Интервал учитывает системную настройку Windows; между кликами повторно проверяются окно и курсор. После ошибки или отмены оставшийся клик не выполняется.

Для перетаскивания предварительно проверьте обе точки одного окна:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --screenshot-target 150 180 --screenshot-drag-target 400 300 --screenshot-ruler
```

На общем PNG метка `1` обозначает начало, `2` — конец. Откройте снимок. Затем отдельным вызовом переместите курсор в начало через `--mouse-move 150 180`, подтвердите его снимком `--screenshot-cursor-crosshair` и просмотрите результат. После этого выполните:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --drag-to 400 300 --drag-button left
```

Перенос выполняется плавно, без джиттера, только в проверенную конечную точку. При отмене кнопка отпускается в текущей позиции; `actual_cursor` показывает место остановки. Автоматического отката переноса нет.

В примерах `$windowId` — актуальный HWND из `--list-windows`. Координаты, заголовки и имена контролов условные.

## Требования

- Windows 10 версии 1703 или новее с активным графическим сеансом и доступом к целевому окну. Требуется режим DPI `per-monitor-v2`. Linux и macOS не поддерживаются.
- CPython для Windows. Проверенное окружение: **Windows 10 x64, CPython 3.14.3 x64, uiautomation 2.0.29**. Минимальная версия Python и совместимость с другими окружениями пока не подтверждены отдельными проверками.
- [uv](https://docs.astral.sh/uv/) для управления окружением и зависимостями. Установка через `pip` также доступна.
- Возможность создавать файлы рядом с `type_text.py`: здесь сохраняются снимки и состояние проверки курсора.

Окна, Win32-контролы, скриншоты, мышь и ввод текста работают на стандартной библиотеке Python через `ctypes` и Windows API. Для PNG не требуется Pillow; для ввода не требуется буфер обмена.

Для команд UI Automation нужен пакет [uiautomation 2.0.29](https://pypi.org/project/uiautomation/2.0.29/). Дополнительный набор `uia` в [pyproject.toml](pyproject.toml) включает также `comtypes==1.4.16`, проверенный с адаптером COM-кэша в памяти. Точные версии и контрольные суммы пакетов сохранены в [uv.lock](uv.lock); [requirements.txt](requirements.txt) оставлен для установки через `pip`. UIA загружается только в служебном процессе, журналы зависимости отключены. Если UI Automation не используется, установку зависимостей можно пропустить.

## Установка

### Через uv

Один раз установите uv официальным установщиком для Windows:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Откройте новый PowerShell, чтобы команда `uv` появилась в `PATH`. Если терминал встроен в редактор, может потребоваться перезапустить редактор. Другие способы приведены в [инструкции установки uv](https://docs.astral.sh/uv/getting-started/installation/).

Скачайте исходники и откройте PowerShell в папке с `type_text.py`. Подготовьте окружение с поддержкой UI Automation и проверьте запуск:

```powershell
uv --version
uv sync --locked --extra uia
uv run --locked --extra uia type_text.py --help
uv run --locked --extra uia type_text.py --text "Тестовый текст" --dry-run --quiet
```

Последняя команда должна вернуть JSON с `ok: true`, `mode: "dry-run"` и `typed_chars: 0`. Она не вводит текст в открытые приложения.

uv создаёт `.venv` и использует CPython **3.14.3**, выбранный в [.python-version](.python-version). Если подходящего интерпретатора нет, uv может скачать его автоматически. В настройках uv-проекта разрешена ветка Python 3.14; отдельные проверки других версий пока не выполнены. Активация окружения для `uv run` не требуется.

Во всех примерах этого README вместо `python .\type_text.py` можно использовать `uv run --locked --extra uia .\type_text.py`. Параметры самого инструмента остаются прежними. `--locked` проверяет соответствие `uv.lock` настройкам проекта и запрещает его автоматическое обновление.

Для работы без UI Automation достаточно `uv sync --locked` и `uv run --locked type_text.py --help`. Обычный `uv sync` без `--extra uia` удаляет дополнительный набор из `.venv`; для дальнейшей работы с UIA снова указывайте `--extra uia`.

`uv run` может создавать окружение и устанавливать пакеты перед запуском, в том числе перед `--dry-run`. Если окружение уже подготовлено и нужен запуск без действий менеджера, используйте `.\.venv\Scripts\python.exe -B .\type_text.py --text "Тестовый текст" --dry-run --quiet`.

### Через pip

При установленном Python можно использовать прежний способ:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r .\requirements.txt
```

Если PowerShell запрещает запуск `Activate.ps1`, используйте `.\.venv\Scripts\python.exe` вместо `python` в команде установки и во всех дальнейших примерах. [Активация виртуального окружения необязательна](https://docs.python.org/3.14/library/venv.html#how-venvs-work). Этот вариант создаёт окружение через `venv`; окружением, созданным через uv, управляйте командами uv.

Проверьте CLI и разбор параметров ввода:

```powershell
python .\type_text.py --help
python .\type_text.py --text "Тестовый текст" --dry-run --quiet
```

Вторая команда должна вернуть JSON с `ok: true`, `mode: "dry-run"` и `typed_chars: 0`. Она не вводит текст в открытые приложения.

## MCP: дополнительный способ управления

CLI продолжает работать самостоятельно. Локальный MCP-сервер предоставляет те же операции подключённому клиенту через `stdio`. Сервер работает в интерактивном сеансе Windows; сетевой порт не открывается.

Установка и запуск:

```powershell
uv sync --locked --extra mcp --extra uia
uv run --locked --extra mcp --extra uia mcp_server.py
```

Обычный запуск ждёт сообщений MCP-клиента. Справка: `uv run --locked --extra mcp mcp_server.py --help`. Для работы без UI Automation опустите `--extra uia`; при запросе UIA вернётся `UIA_UNAVAILABLE`. Точка входа CLI не импортирует SDK MCP и работает без его установки.

Для режима наблюдения добавьте `--read-only`: доступны статус, окна, курсор, снимки и контролы; инструменты ввода и изменения окон не предоставляются. Снимки и проверки цели при этом по-прежнему сохраняются на диск. Само подключение клиента не создаёт рамку, не делает снимок и не отправляет ввод.

### Подключение клиента

Для клиентов с секцией `mcpServers` подходит следующий шаблон. Замените путь на каталог своей копии инструмента; при необходимости укажите полный путь к `uv.exe`. Формат конфигурации других клиентов может отличаться.

```json
{
  "mcpServers": {
    "desktop-action": {
      "command": "uv",
      "args": [
        "--directory", "C:/Projects/DesktopActionTool",
        "run", "--locked", "--extra", "mcp", "--extra", "uia",
        "mcp_server.py"
      ]
    }
  }
}
```

Конфигурация клиента не изменяется автоматически. При запуске сервер получает отдельный процесс для каждого вызова CLI и использует общий каталог настроек, снимков и состояния этой копии проекта.

### Проверка ветки mcp в Kilo Code

Ветка `mcp` содержит версию разработки `0.2.0.dev0` для проверки перед слиянием. На другом компьютере с Windows скачайте её в отдельный каталог и подготовьте окружение:

```powershell
git clone --branch mcp --single-branch https://github.com/zibitpnz/DesktopActionTool.git DesktopActionTool-mcp
cd DesktopActionTool-mcp
uv sync --locked --extra mcp --extra uia
uv run --locked --extra mcp --extra uia mcp_server.py --help
```

В Kilo откройте настройки MCP, добавьте сервер типа **Local (stdio)** и задайте команду запуска. В [текущем формате Kilo](https://kilo.ai/docs/automate/mcp/using-in-kilo-code) запись в `kilo.jsonc` выглядит так; замените каталог на свой, сохранив остальные имеющиеся настройки:

```json
{
  "mcp": {
    "desktop-action": {
      "type": "local",
      "command": [
        "uv", "--directory", "C:/Projects/DesktopActionTool-mcp",
        "run", "--locked", "--extra", "mcp", "--extra", "uia",
        "mcp_server.py"
      ],
      "enabled": true,
      "timeout": 120000
    }
  }
}
```

Здесь `timeout` Kilo задан в миллисекундах, а `operation_timeout_s` инструмента — в секундах. Для операций дольше двух минут увеличьте также таймаут клиента. Если Kilo не находит `uv`, укажите полный путь к `uv.exe`. В версиях клиента, использующих конфигурацию `mcpServers`, применяйте шаблон из предыдущего раздела с подходящим путём.

Kilo сам запускает сервер и управляет подключением; заранее открывать `mcp_server.py` в отдельном терминале не требуется. Начните проверку с `desktop_status` и чтения `desktopaction://help/windows`, затем запросите список окон и снимок выбранного окна. Должны быть доступны 24 инструмента и 6 ресурсов справки; убедитесь, что модель получает изображение. После этого в согласованное время проверьте Калькулятор `12 + 23 = 35` отдельными шагами мыши. Сохраните версию Kilo, модель, масштаб экрана и ошибки, если они появятся, для решения о слиянии ветки.

### Инструменты MCP

| Группа | Инструменты |
| --- | --- |
| Состояние и окна | `desktop_status`, `list_windows`, `active_window`, `cursor_position` |
| Снимки и контролы | `capture_window`, `preview_target`, `list_controls`, `wait_control` |
| Сеанс рамки | `session_start`, `session_status`, `session_heartbeat`, `session_end` |
| Изменение окна | `focus_window`, `resize_window`, `set_window_rect`, `minimize_window` |
| Мышь | `move_mouse`, `click_mouse`, `double_click_mouse`, `scroll_mouse`, `drag_mouse` |
| Клавиатура | `type_text`, `press_key`, `hotkey` |

Точные параметры, диапазоны и описания возвращаются через `tools/list`. Неизвестные параметры отклоняются; вызова произвольной оболочки, массива CLI-флагов или чтения произвольного файла нет. `press_key` поддерживает Enter, Delete и Backspace; остальные поддерживаемые клавиши и сочетания доступны через `hotkey`.

Для действия передайте `target` одним из способов: `{"window_id": 12345}`, `{"window_title": "Заголовок", "process_name": "app.exe"}` или `{"session_id": "идентификатор сеанса"}`. HWND берётся из `list_windows`; значения здесь условные. В случае активного сеанса MCP требует явного `target.session_id` из `session_start`/`session_status`; указание HWND не означает автоматического присоединения к нему. CLI сохраняет прежнее наследование привязанного окна.

Пример последовательности MCP-вызовов для координат окна:

1. `preview_target` с `target`, `point: {"x": 150, "y": 180}` и `coord_origin: "window"`. Откройте полученное изображение и сохраните `verification_id`.
2. `move_mouse` с той же целью, точкой, системой координат и полученным `verification_id`. По умолчанию выполняется снимок после наведения; откройте его и используйте **новый** `verification_id` из этого ответа.
3. `click_mouse` с `target`, `button: "left"` и идентификатором проверенного курсора. Повторное нажатие потребует новой проверки.

Если `move_mouse` вызван с `screenshot_after: false`, его идентификатор описывает стадию `moved_unverified`. Сначала вызовите `capture_window` с `cursor_crosshair: true` и этим идентификатором, затем проверьте PNG. Идентификаторы действуют в текущем процессе MCP, связаны с точным состоянием CLI и ограничены временем проверки из настроек. Замена состояния другой командой приводит к `VERIFICATION_CHANGED`; наличие токена не подтверждает, что изображение действительно было просмотрено.

Модифицирующие инструменты поддерживают `dry_run`; он сохраняет обычный режим построения плана CLI. Для поддерживаемых действий доступны `screenshot_after` и `screenshot_delay_ms`; `initial_delay_s` регулирует начальную задержку ввода. `operation_timeout_s` задаёт общий предел вызова, по умолчанию 60 секунд, максимум 600. Таймаут ожидания UIA задаётся отдельно через `timeout_s`.

Ответ содержит обычный JSON CLI в `structuredContent` и текстовом блоке, а снимки — в блоках `image/png`. Координаты и разрешение не изменяются скрыто. По умолчанию суммарный размер PNG ограничен 8 МиБ; его можно уменьшить параметром сервера `--max-image-mib`. При недоступном или слишком большом изображении возвращается `IMAGE_DELIVERY_FAILED`. Если действие уже выполнено, сохраняются `action_completed` и `action_result`: повторять его автоматически нельзя.

### Инструкции модели и справка по запросу

При подключении сервер передаёт короткую памятку: явный выбор окна/сеанса, порядок «предварительный снимок → наведение → снимок курсора → клик», проверка текста перед Enter и запрет повторения действия с неизвестным результатом. Описания и схемы 24 инструментов доступны через `tools/list`.

Подробная справка хранится в `mcp_contract.py` и выдаётся отдельными ресурсами MCP. `resources/list` возвращает только названия, описания и размеры разделов; `resources/read` — текст **одного** указанного раздела:

| URI ресурса | Тема |
| --- | --- |
| `desktopaction://help/windows` | Выбор, фокусировка и переключение окон; привязанные сеансы |
| `desktopaction://help/mouse` | Проверки снимков, наведение, клик и перенос |
| `desktopaction://help/keyboard` | Unicode, сочетания клавиш, Enter и копирование между приложениями |
| `desktopaction://help/controls` | Win32/UIA-контролы, селекторы и ожидание |
| `desktopaction://help/screenshots` | Снимки, задержки, координаты и объём ответа |
| `desktopaction://help/recovery` | Ошибки, частичное выполнение, отмена и восстановление |

Пример запроса протокола: `resources/read` с `{"uri":"desktopaction://help/mouse"}`. Клиент может предоставлять модели собственную команду чтения ресурсов. Общая памятка рекомендует читать только нужную тему при незнакомой операции или ошибке. В ошибочных результатах инструментов поле `help_resource` указывает подходящий раздел; готовый текст справки в каждый ответ не добавляется. Нарушения MCP-схем параметров и неизвестные URI возвращают протокольную ошибку `-32602`.

Справка доступна и с `--read-only`. Её чтение не запускает CLI, не создаёт снимки/сеансы и не читает произвольные файлы или URL. Разделы содержат примеры для полного набора возможностей; доступность конкретных инструментов определяется `tools/list` и режимом сервера.

README автоматически в контекст модели не загружается. Сам сервер также не передаёт содержимое всех разделов при подключении; как клиент сохраняет прочитанную справку и историю изображений, определяется клиентом. Например, [Kilo поддерживает инструкции сервера и чтение ресурсов](https://kilo.ai/docs/automate/mcp/using-in-kilo-code#server-instructions-and-resources).

Для уменьшения объёма схем сокращены повторяющиеся условия выбора цели; исключительность HWND/селекторов/сеанса сохранена. Текстовое представление JSON записывается компактно и сохраняет Unicode без лишнего экранирования. Полный `structuredContent`, поля частичного выполнения и PNG сохранены; справка и изменения форматирования не заменяют проверки безопасности в коде.

### Совместная работа и отмена

CLI и MCP могут оставаться запущенными одновременно. Общий mutex защищает действия **одной копии проекта**; параллельные изменяющие вызовы не ставятся в очередь и возвращают `BUSY`. Отдельные копии с разными каталогами состояния не координируются этой блокировкой.

Отмена MCP-запроса, таймаут, закрытие соединения и выход управляющего процесса передаются CLI отдельным сигналом Windows. Инструмент завершает действие с освобождением зарегистрированных нажатий; Esc остаётся доступен. Сервер не посылает искусственный Esc в пользовательское приложение. Итог прерванного вызова можно проверить через `desktop_status`, даже если клиент уже перестал ждать исходный ответ.

Если дочерний процесс пришлось завершить принудительно либо освобождение ввода не подтверждено, создаётся `.mcp_recovery.json`, а новые действия блокируются с `INPUT_RECOVERY_REQUIRED`. Проверьте целевое окно и удерживаемые клавиши/кнопки, устраните оставшийся ввод, затем вручную удалите этот файл и перезапустите MCP-сервер. Автоматического повторения действия или сброса такой блокировки нет.

Сервер отслеживает созданный им сеанс рамки и при отключении закрывает его только при совпадении `session_id`. Чужой или заменивший его сеанс автоматически не завершается. Для перехода в другое приложение используйте нынешний порядок: завершите сеанс, выберите новое окно и начните новый сеанс.

## Индикатор работы и сеансы

По умолчанию перед действием на каждом подключённом мониторе появляется тонкая оранжевая рамка с надписью «Работает DesktopActionTool — не трогайте мышь и клавиатуру». Она пропускает клики, не забирает фокус и не появляется в списке рабочих окон. Рамка предупреждает пользователя; физическая мышь и клавиатура остаются доступны, в том числе для отмены.

При одиночном вызове рамка появляется до выполнения действия и исчезает после его завершения вместе с возможным `--screenshot-after`. Перед началом работы новой рамки добавляется пауза 500 мс. Чтение списка окон/контролов и отдельный снимок не создают рамку; `--help` и `--dry-run` также её не показывают.

Для нескольких команд, между которыми оператор или модель рассматривает снимки, выберите `$windowId` из `--list-windows` и начните сеанс с привязкой:

```powershell
python .\type_text.py --window-id $windowId --session-start
```

Теперь рамка остаётся видимой между вызовами этой копии инструмента. Обычные команды продлевают сеанс. Чтобы продлить его во время долгого анализа, используйте:

```powershell
python .\type_text.py --session-heartbeat
```

Проверка состояния не продлевает сеанс:

```powershell
python .\type_text.py --session-status
```

После завершения работы:

```powershell
python .\type_text.py --session-end
```

По умолчанию сеанс завершается после **120 секунд без команд**. Длительная выполняющаяся команда не считается бездействием; отсчёт начинается заново после её окончания. Другой интервал можно задать при запуске:

```powershell
python .\type_text.py --window-id $windowId --session-start --session-timeout-s 300
```

Если сеансом управляет долгоживущий процесс, укажите его PID. Например, для команд из одного постоянно открытого PowerShell:

```powershell
python .\type_text.py --window-id $windowId --session-start --session-owner-pid $PID
```

При завершении этого процесса рамка снимается, даже если таймаут ещё не истёк. Короткоживущая оболочка отдельного вызова для этой привязки не подходит. Если постоянного управляющего процесса нет, используйте таймаут и `--session-heartbeat`.

Ошибка выполнения или отмена команды закрывает связанный сеанс. Между командами сеанс также можно завершить клавишей Esc; `--no-abort-key` при `--session-start` отключает это поведение. Во время команды действует её собственный параметр `--no-abort-key`. Если сеанс завершён извне, текущая команда замечает это и прекращает действия с освобождением удерживаемого ввода.

Скриншоты инструмента не содержат рамку: перед захватом она кратковременно скрывается, процесс индикатора ожидает обновления изображения, после захвата рамка восстанавливается. Ошибка скрытия блокирует захват. На Windows 10 версии 2004 и новее дополнительно запрашивается [исключение окна из захвата](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity); собственный захват инструмента использует скрытие независимо от поддержки этого механизма.

Настройки в `settings.json`:

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `activity_frame_enabled` | `1` | Автоматическая рамка для одиночных действий; `0` отключает её |
| `activity_frame_width_px` | `12` | Полная ширина рамки вместе с затуханием в физических пикселях, от 1 до 32 |
| `activity_frame_gradient_enabled` | `1` | Плавное затухание от внешнего края к полной прозрачности внутри; `0` — равномерная прозрачность |
| `activity_frame_opacity_percent` | `90` | Непрозрачность внешнего края, от 1 до 100%; без градиента применяется ко всей рамке |
| `activity_frame_lead_ms` | `500` | Пауза после появления новой автоматической рамки до действия; не заменяет `--initial-delay-s` |
| `activity_session_timeout_s` | `120` | Таймаут бездействия сеанса, от 1 до 86400 секунд |

Ключи `--activity-frame` и `--no-activity-frame` переопределяют автоматическую рамку для одного вызова. `--no-activity-frame` не закрывает уже начатый сеанс — для этого служит `--session-end`.

Градиент направлен от края монитора к центру: рабочая область за рамкой постепенно становится полностью видимой. При ширине 1 пиксель затухания нет. Плашка с текстом остаётся непрозрачной для читаемости. Изменения оформления применяются при следующем появлении рамки; для активного сеанса выполните `--session-end`, затем `--session-start --window-id $windowId`. Чтобы вернуть прежнюю сплошную рамку, задайте ширину `4`, градиент `0`, непрозрачность `100`.

## Быстрый старт

Все примеры ниже выполняются из папки проекта в PowerShell. Получите текущие окна и задайте `$windowId` из поля `id` нужного окна:

```powershell
python .\type_text.py --list-windows
$windowId = [int64](Read-Host "Введите id нужного окна из списка")
```

Повторно получайте список после закрытия или перезапуска приложения: HWND может измениться или быть присвоен другому окну. В примерах координаты, размеры окон и имена контролов условные — подбирайте их по текущему снимку или списку элементов.

Команды в пошаговых сценариях запускаются отдельно. Между снимком и действием откройте PNG по пути из JSON и проверьте цель; не выполняйте весь сценарий одним блоком без просмотра снимков.

Сфокусировать нужное окно:

```powershell
python .\type_text.py --window-id $windowId --focus-only --quiet
```

Сделать рекомендуемый скриншот для анализа нейросетью:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --screenshot-cursor-crosshair --screenshot-ruler
```

Проверить предполагаемую цель без перемещения мыши:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --screenshot-ruler --screenshot-target 245 98
```

Плавно переместить курсор в координаты окна и получить проверочный снимок через 500 мс после остановки:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --mouse-move 245 98 --smooth-move --screenshot-after --screenshot-ruler --quiet
```

Открыть `screenshot.path` из JSON и проверить позицию курсора. Если создан увеличенный фрагмент, проверить также `screenshot.cursor_detail_screenshot.path`. Кроссхэйр курсора после перемещения добавляется автоматически.

Кликнуть отдельным вызовом:

```powershell
python .\type_text.py --window-id $windowId --click left --quiet
```

## Протокол действий

Оператор или модель должны работать маленькими проверяемыми шагами.

1. Найти нужное окно через `--list-windows` или `--active-window`.
2. Сфокусировать окно через `--window-id ... --focus-only`.
3. Сделать скриншот с `--coord-origin window --screenshot-cursor-crosshair --screenshot-ruler`.
4. Определить координаты цели по скриншоту.
5. Сделать проверочный скриншот с виртуальной целью: `--screenshot-target X Y`.
6. Убедиться, что красный прицел стоит на нужном элементе.
7. Переместить курсор через `--coord-origin window --mouse-move X Y --smooth-move`; ключ `--screenshot-after` сразу добавит последующий снимок.
8. Просмотреть полученный снимок и убедиться, что голубой кроссхэйр реального курсора стоит на цели. Без `--screenshot-after` сделать снимок отдельной командой.
9. Только после подтверждения выполнить `--click left`, `--click right` или ввод текста.
10. После клика или ввода проверить результат на снимке, полученном через `--screenshot-after` или отдельной командой.

Важное правило: не перемещай мышь без предварительной красной мишени. После `--screenshot-target X Y` или успешной одиночной подсветки UIA-контрола инструмент сохраняет цель, и следующий `--mouse-move` разрешён только если он ведёт в эту же точку. Если модель попытается перепрыгнуть шаг мишени или поехать в другие координаты, `--mouse-move` будет заблокирован.

Важное правило: не совмещай перемещение мыши и клик в одной команде. Перемещение можно объединить с последующим снимком через `--screenshot-after`. После просмотра снимка выполняй `--click` отдельным вызовом.

Инструмент принудительно хранит это правило между запусками. После успешного `--mouse-move` или `--mouse-move-relative` клик блокируется до проверочного снимка курсора. При `--screenshot-after` снимок и проверка выполняются в конце того же вызова; иначе нужна отдельная команда `--screenshot-window --screenshot-cursor-crosshair`. Если включён `paired_cursor_screenshot_enabled`, проверяй также увеличенный фрагмент: `screenshot.cursor_detail_screenshot.path` в объединённом ответе или `cursor_detail_screenshot.path` у отдельного снимка.

Инструмент проверяет последовательность команд, а содержимое снимков оценивает оператор или внешняя модель. Сам факт создания PNG не подтверждает, что выбрана нужная кнопка или поле. Перед `Enter` проверка текста также выполняется оператором или моделью.

Проверка действует **120 секунд** с момента снимка цели и используется один раз. Допуск по умолчанию — **0 пикселей**. Перед кликом сверяются HWND, PID, время создания процесса, геометрия, DPI, активное окно и положение курсора. Перекрытая другим окном цель блокируется. Снимок другого окна не разрешает клик. Пустое, повреждённое или старое состояние также требует нового цикла проверки.

Разрешение расходуется до отправки нажатия. Ошибка, отмена, ввод текста, прокрутка и отдельные изменения окна аннулируют проверку. Параллельное действие из той же копии инструмента получает `BUSY`. Изменения содержимого приложения при прежней геометрии автоматически не распознаются; изображение всё равно нужно просматривать.

Неправильно:

```powershell
python .\type_text.py --window-id $windowId --coord-origin client --mouse-move 300 50 --smooth-move --quiet
python .\type_text.py --window-id $windowId --coord-origin client --mouse-move 300 50 --smooth-move --click left --quiet
python .\type_text.py --window-id $windowId --coord-origin client --mouse-move 300 50 --smooth-move; if ($?) { python .\type_text.py --window-id $windowId --click left }
```

Правильно:

```powershell
python .\type_text.py --window-id $windowId --coord-origin client --screenshot-window --screenshot-ruler --screenshot-target 300 50
python .\type_text.py --window-id $windowId --coord-origin client --mouse-move 300 50 --smooth-move --quiet
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --screenshot-cursor-crosshair --screenshot-ruler
python .\type_text.py --window-id $windowId --click left --quiet
```

## JSON-ответы

Рабочие команды возвращают краткий JSON в `stdout`. Проверяйте поле `ok`, а затем результат на снимке. Подсказки о выполнении идут в `stderr`; флаг `--quiet` скрывает их, сохраняя JSON. Справка `--help` и ошибки синтаксиса аргументов оформляются стандартным `argparse` и не являются JSON.

Сокращённый пример ответа при скриншоте. HWND, имя файла и каталог условные; реальная команда возвращает абсолютный путь к созданному PNG:

```json
{
  "ok": true,
  "mode": "screenshot-window",
  "window_id": 67108,
  "path": "C:\\Projects\\DesktopActionTool\\screenshots\\screenshot_20260101_120000_000_window_67108.png",
  "width": 1096,
  "height": 921,
  "content_width": 1000,
  "content_height": 825
}
```

Пример ответа при вводе текста:

```json
{
  "ok": true,
  "mode": "type",
  "typed_chars": 11,
  "planned_chars": 11,
  "aborted": false,
  "final_enter_sent": false,
  "elapsed_ms": 1136
}
```

Коды завершения: `0` — успешное выполнение, `1` — обработанная ошибка, `2` — прерывание или ошибка синтаксиса командной строки. При обработанной ошибке JSON содержит `ok: false` и `error`; при блокировке мыши поле `action_state` помогает определить требуемый следующий шаг.

## Снимок после действия

Ключ `--screenshot-after` добавляет снимок окна после успешного завершения действия. Поддерживаются перемещение мыши, обычный и двойной клик, перетаскивание, прокрутка, ввод текста, клавиатурные команды, фокусировка и изменение позиции/размера окна. Без этого ключа поведение остаётся прежним.

Задержка отсчитывается после окончания действия: остановки курсора, отпускания кнопки мыши, завершения всей прокрутки или ввода. Значение `screenshot_delay_ms` в `settings.json` задаёт задержку по умолчанию — **500 мс**. Ключ `--screenshot-delay-ms` переопределяет её для одного вызова; `0` означает отсутствие дополнительного ожидания. Он применяется только вместе с `--screenshot-after`; обычная команда `--screenshot-window` сохраняет снимок сразу.

После предварительного снимка цели и его просмотра можно переместить курсор и подождать появления подсказки:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --mouse-move 245 98 --smooth-move --screenshot-after --screenshot-delay-ms 1500 --screenshot-ruler
```

Сначала просмотрите полученный снимок. Затем отдельным вызовом выполните клик и получите результат после ожидания обновления интерфейса:

```powershell
python .\type_text.py --window-id $windowId --click left --screenshot-after --screenshot-delay-ms 1500
```

Для ввода текста работает тот же ключ:

```powershell
python .\type_text.py --window-id $windowId --text "Пример текста" --screenshot-after
```

Путь к PNG находится в `screenshot.path`, увеличенный фрагмент курсора — в `screenshot.cursor_detail_screenshot.path`. Основные поля результата действия сохраняются; добавляются `action_completed`, `screenshot_delay_ms` и `total_elapsed_ms` для всего вызова. Поле `elapsed_ms` сохраняет прежний смысл времени самого действия. При `--dry-run` возвращается только план с `screenshot.planned: true`: ожидание, ввод, запись состояния и создание PNG не выполняются.

После перемещения снимок автоматически содержит кроссхэйр курсора и выполняет ту же проверку, что отдельный `--screenshot-window --screenshot-cursor-crosshair`. Для других действий кроссхэйр можно добавить явно. Поддерживаются `--screenshot-ruler`, `--controls-overlay` и `--uia-controls-overlay`. Создание новой мишени и одиночная UIA-подсветка остаются отдельными командами. Действующее разрешение на клик не продлевается на время ожидания, а снимок после клика не разрешает повторный клик.

Снимается окно из `--window-id` или селектора. Без явного выбора для наведения, клика и перетаскивания используется окно сохранённой цели, для остальных действий — активное окно в начале действия. Если действие откроет другое окно, инструмент автоматически на него не переключится. Снимок содержит видимую область экрана в границах выбранного окна: часть подсказки за этими границами не попадёт в PNG. Фиксированная задержка не гарантирует готовность приложения; при необходимости увеличьте её и проверьте изображение.

Ожидание можно прервать Esc или Ctrl+C; блокировка параллельных действий удерживается до завершения снимка. Если действие уже выполнено, но ожидание или снимок завершились ошибкой, ответ содержит `ok: false`, `action_completed: true`, `failed_stage: "screenshot-after"` и исходный `action_result`. Не повторяйте автоматически выполненный ввод: проверьте результат и при необходимости запросите отдельный снимок. Состояние разрешения на клик при такой ошибке аннулируется.

## Скриншоты и подтверждения

Обычный скриншот окна:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window
```

Рекомендуемый режим для нейросети:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --screenshot-cursor-crosshair --screenshot-ruler
```

Скриншот с рамками Win32-контролов:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --controls-overlay --screenshot-ruler
```

Отдельно получить список Win32-контролов в JSON:

```powershell
python .\type_text.py --window-id $windowId --list-controls
```

Скриншот с рамками UI Automation-контролов:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --uia-controls-overlay --uia-control-types ButtonControl --screenshot-ruler
```

Скриншот с подсветкой только одного UI Automation-контрола:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --uia-highlight-automation-id num5Button --uia-control-types ButtonControl --screenshot-ruler
```

Отдельно получить список UI Automation-контролов в JSON:

```powershell
python .\type_text.py --window-id $windowId --uia-list-controls --uia-control-types ButtonControl
```

Оба списка возвращаются во вложенном массиве `controls.controls`. Например, сохранить текущий UIA-список в переменную PowerShell и вывести основные поля можно так:

```powershell
$uiaResult = python .\type_text.py --window-id $windowId --uia-list-controls --uia-control-types ButtonControl,EditControl | ConvertFrom-Json
if (-not $uiaResult.ok) { throw $uiaResult.error }
$uiaResult.controls.controls | Select-Object id, name, control_type, automation_id, click_point
```

Контролы используются для обнаружения элементов и выбора точки действия. Нажатие выполняется мышью после подсветки, наведения и проверки курсора. Доступность элементов зависит от приложения: пустой список не обязательно означает ошибку инструмента.

`--screenshot-cursor-crosshair` добавляет голубые полупрозрачные линии, пересекающиеся в позиции курсора.

Если в `settings.json` включён `paired_cursor_screenshot_enabled`, при использовании `--screenshot-cursor-crosshair` создаётся второй парный скриншот фактического положения курсора. В JSON путь к нему находится в `cursor_detail_screenshot.path`. Это такая же увеличенная лупа с линейкой, как у красной цели, но с голубым кроссхэйром реального курсора. Используй её, когда нужно понять, насколько точно курсор уже стоит на нужном элементе после перемещения.

`--screenshot-target X Y` добавляет красный полупрозрачный виртуальный прицел в заданной точке. Прицел виден только на PNG и не двигает реальную мышь. Координаты цели читаются в системе `--coord-origin`, поэтому для работы по скриншоту обычно используется `--coord-origin window`.

Пример проверки цели перед реальным движением мыши:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --screenshot-ruler --screenshot-target 245 98
```

Если в `settings.json` включён `paired_target_screenshot_enabled`, при использовании `--screenshot-target` создаётся второй парный скриншот предполагаемой цели. Основной скриншот получает компактную пометку `DETAIL`, а в JSON появляется путь `target_detail_screenshot.path`.

Парный скриншот — это увеличенная область вокруг цели. По умолчанию он берёт `40 px` во все стороны от центра цели, увеличивает фрагмент в `8x` и рисует отдельную линейку с реальными координатами окна и шагом `5 px`. Круг красной мишени на парном скриншоте масштабируется вместе с увеличением: при основном радиусе `19 px` и `paired_target_zoom = 8` радиус круга на детальном снимке будет `152 px`. Его нужно использовать для точной поправки координат перед реальным перемещением мыши.

Можно совместить реальный кроссхэйр курсора и виртуальную цель:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --screenshot-cursor-crosshair --screenshot-ruler --screenshot-target 245 98
```

На таком скриншоте голубой кроссхэйр показывает фактическое положение мыши, а красный прицел показывает предполагаемую цель для будущего перемещения.

`--screenshot-ruler` добавляет внешнюю координатную линейку вокруг изображения. Сам скриншот окна остается чистым внутри рамки, а координаты проще оценивать по рискам.

Важно: линейка показывает координаты содержимого окна в выбранной системе `--coord-origin`, а не координаты итогового PNG-файла. Внешнее поле линейки не входит в координаты цели. Если на скриншоте с линейкой точка выглядит как `x=178`, не нужно прибавлять или вычитать `screenshot_ruler_margin_px` вручную: передавай именно значение с линейки в `--screenshot-target X Y` или `--mouse-move X Y`. Типовая ошибка - целиться по пикселям всего PNG и забыть, что вокруг окна добавлено поле линейки; тогда мишень смещается на размер этого поля, обычно на `48 px`.

`--controls-overlay` добавляет рамки и числовые ID дочерних Win32-контролов поверх скриншота. В JSON поле `controls_overlay.controls` содержит `id`, `name`, `class_name`, координаты `screen_rect`, `window_rect`, `client_rect` и рекомендуемую точку `click_point`. Состав списка зависит от того, какие дочерние окна предоставляет приложение. Браузерные и самостоятельно отрисованные интерфейсы могут предоставлять только общие контейнеры.

`--uia-controls-overlay` добавляет рамки и числовые ID Windows UI Automation-контролов. Этот способ позволяет работать с элементами, которые приложение предоставляет через UIA. В JSON поле `uia_controls_overlay.controls` содержит `id`, `name`, `control_type`, `automation_id`, `class_name`, координаты `screen_rect`, `window_rect`, `client_rect`, точку `click_point` в координатах окна и `screen_click_point` в координатах экрана. Для уменьшения шума используй фильтр `--uia-control-types ButtonControl` или список через запятую, например `ButtonControl,EditControl`.

`--uia-highlight-automation-id`, `--uia-highlight-name` и `--uia-highlight-control-id` подсвечивают только один UI Automation-контрол. На скриншоте рисуется зелёная рамка выбранного контрола и красная мишень в его `click_point`. В JSON поле `uia_control_highlight.selected_control` содержит выбранный контрол, а `uia_control_highlight.target` содержит точку для `--mouse-move` в координатах окна. Если включён `paired_target_screenshot_enabled`, создаётся детальный парный скриншот этой точки. Если включён `uia_highlight_control_screenshot_enabled`, дополнительно создаётся чистый увеличенный снимок самого контрола без номера и мишени; путь находится в `uia_highlight_control_screenshot.path` и `uia_control_highlight.control_screenshot_path`. Успешная подсветка одного контрола также записывает `click_point` как проверенную цель для следующего `--mouse-move`.

Для одиночной подсветки лучше использовать `--uia-highlight-automation-id`, если он есть. Числовой `--uia-highlight-control-id` зависит от текущего порядка обхода, `--uia-control-types`, `--controls-limit` и других фильтров, поэтому используй его только с теми же параметрами, с которыми был получен список `--uia-list-controls`.

По умолчанию линейка:

- поле вокруг скриншота: `48 px`;
- мелкие риски: каждые `50 px`;
- подписи и крупные риски: каждые `50 px`;
- горизонтальные подписи чередуются по высоте, чтобы длинные значения не накладывались друг на друга.

Можно изменить параметры:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --screenshot-window --screenshot-cursor-crosshair --screenshot-ruler --screenshot-ruler-margin-px 60 --screenshot-ruler-step-px 25 --screenshot-ruler-major-step-px 50
```

Важно: скриншот делается с видимой области экрана. Если окно закрыто другим окном, на снимок может попасть перекрывающее окно. Перед скриншотом лучше вызвать `--focus-only`.

Папка `screenshots` создаётся автоматически рядом со скриптом и очищается после каждого скриншота. Количество последних PNG-файлов задаётся настройкой `screenshot_keep_count`. В лимит входят также детальные снимки цели, курсора и контрола: это лимит файлов, а не операций. Значение `-1` отключает удаление старых скриншотов.

## Координаты

Внутренние координаты выражены в физических пикселях. Режим `per-monitor-v2` устанавливается до получения геометрии и UIA-чтения. `coordinate_context.dpi` содержит режим, DPI окна и монитор; DPI окна зависит от awareness целевого приложения и не всегда равен масштабу монитора. Отрицательные координаты поддерживаются. В выделенном нативном окне проверены четыре монитора при 100%, снимки, Win32/UIA, клики и перенос при 125%/150%, а также отказ от старого снимка при переходах 100% ↔ 125% и 100% ↔ 150%. Другие приложения и режимы DPI, одновременная пара мониторов 125% + 150% и смена масштаба при неподвижном окне отдельно не проверялись.

Координаты можно задавать в трех системах:

- `screen` - абсолютные координаты рабочего стола Windows;
- `window` - координаты относительно левого верхнего угла внешней рамки окна;
- `client` - координаты относительно клиентской области окна.

По умолчанию используется `screen`. В примерах скриншотов обычно явно указан `--coord-origin window`: координаты отсчитываются от рамки окна без внешнего поля линейки. Для мишени, линейки и перемещения используйте одну систему координат.

Получить текущую позицию курсора в координатах экрана:

```powershell
python .\type_text.py --cursor-position
```

Получить позицию курсора относительно окна:

```powershell
python .\type_text.py --window-id $windowId --coord-origin window --cursor-position
```

Получить позицию курсора относительно клиентской области:

```powershell
python .\type_text.py --window-id $windowId --coord-origin client --cursor-position
```

```powershell
python .\type_text.py --window-id $windowId --scroll-ticks 100 --scroll-direction up --scroll-jitter --quiet
```

Скролл выполняется пачками. Например, если `scroll_batch_size = 10`, команда на `100` тиков будет выполнена как 10 серий по 10 тиков с более длинными паузами между сериями.

## Ввод текста

Ввести текст в активное поле:

```powershell
python .\type_text.py --window-id $windowId --text "Привет, это тест" --quiet
```

Ввести текст в конкретное окно после фокусировки:

```powershell
python .\type_text.py --window-id $windowId --focus-only --quiet
python .\type_text.py --window-id $windowId --text "Привет, это тест" --quiet
```

Ввести текст из stdin:

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$env:PYTHONIOENCODING = "utf-8"
"Тестовый текст" | python .\type_text.py --window-id $windowId --stdin --quiet
```

Настройка UTF-8 в этом примере сохраняет кириллицу при передаче текста из PowerShell в Python. Для текста из файла `--text-file` по умолчанию используется UTF-8; другую кодировку можно задать через `--encoding`.

Ввести текст из файла:

```powershell
python .\type_text.py --window-id $windowId --text-file .\message.txt --quiet
```

Перенос строки через `Shift+Enter`:

```powershell
python .\type_text.py --window-id $windowId --text "Первая строка`nВторая строка" --newline shift-enter --quiet
```

Отправить `Enter` после ввода:

```powershell
python .\type_text.py --window-id $windowId --press-enter --quiet
```

`Enter` всегда выполняется отдельным вызовом. Нельзя совмещать ввод текста и `Enter` в одной команде: после ввода нужно сделать скриншот, проверить текст в поле и только затем вызвать `--press-enter`.

Это правило относится к подтверждению или отправке формы. Параметр `--newline` отдельно определяет, как передавать переносы строк внутри текста: по умолчанию `shift-enter`; режим `enter` отправляет настоящий `Enter` на каждом переносе и в некоторых приложениях может отправлять сообщения. Выбирайте режим с учётом поведения целевого поля.

Старый флаг `--send-enter-at-end` отключен. Если модель попробует его использовать, инструмент вернет ошибку и подскажет сделать отдельный вызов `--press-enter`.

Перед вводом и отдельными клавиатурными действиями по умолчанию есть пауза `3` секунды (`--initial-delay-s`). Если окно выбрано явно, потеря его фокуса останавливает дальнейший ввод. Unicode передаётся в UTF-16; символы вне BMP, включая эмодзи, отправляются суррогатной парой.

Esc прерывает задержки, набор, движение, прокрутку и ожидание UIA, если не задан `--no-abort-key`. При выходе инструмент освобождает удерживаемые им клавиши и кнопки. Ctrl+C в терминале также прерывает выполнение. Уже выполненная часть действия не отменяется; синхронные Windows API не всегда прерываются немедленно.

## Диагностика и ограничения

| Ситуация | Что проверить |
| --- | --- |
| `TARGET_REQUIRED` | Указать окно явно или начать `--session-start --window-id ID` |
| `SESSION_TARGET_MISMATCH` / `SESSION_TARGET_REQUIRED` | Проверить `--session-status`; для новой цели завершить сеанс и начать его с нужным окном |
| `SESSION_CHANGED` | Сеанс завершён или заменён до начала действия; заново проверить цель и сеанс |
| `FOCUS_CHANGED` / `WINDOW_CHANGED` / `TARGET_OCCLUDED` | Остановиться и проверить окно; при необходимости явно восстановить фокус и повторить визуальную проверку цели |
| `UI Automation support requires the 'uiautomation' package` | Для uv запускать с `uv run --locked --extra uia .\type_text.py ...`. Для окружения, созданного через `venv`, выполнить `python -m pip install -r .\requirements.txt` тем же интерпретатором, которым запускается инструмент |
| `STATE_REQUIRED` / `VERIFICATION_REQUIRED` | Создать и просмотреть снимок с мишенью, выполнить наведение и подтвердить курсор |
| `requested destination does not match` | Повторно поставить мишень в нужную точку; проверить HWND и `--coord-origin` |
| `CURSOR_MISMATCH` | Проверить фактическую точку курсора; повторить цикл, если она изменилась |
| Список контролов пуст | Проверить окно, фильтр типов и глубину UIA; при необходимости определить цель по снимку |
| На снимке другое окно | Сфокусировать целевое окно отдельным вызовом `--focus-only`: захватывается видимая область экрана |
| Окно свёрнуто или HWND устарел | Получить новый список окон и восстановить нужное через `--window-id $windowId --focus-only` |

`--dry-run` действует для всех режимов, включая фокусировку, изменение размеров и положения, сворачивание и снимки. Он возвращает план действий, а команды чтения — данные. Ожидание возвращает план без опроса. Окна, ввод, снимки и файл состояния не изменяются. `executable` и `preconditions`, когда присутствуют, описывают проверенные предпосылки; план не гарантирует, что они сохранятся до реального запуска.

Коды завершения: `0` — успех, `1` — ошибка, `2` — отмена или синтаксическая ошибка CLI. При отмене JSON содержит `aborted: true` и счётчики `completed`; после прерванного переноса также `actual_cursor`. `RELEASE_FAILED` сообщает об ошибке отпускания в `release_errors`.

Основные машинные ошибки: `STATE_REQUIRED`, `STATE_CORRUPT`, `STATE_VERSION`, `VERIFICATION_REQUIRED`, `TARGET_EXPIRED`, `CLOCK_CHANGED`, `WINDOW_CHANGED`, `FOCUS_CHANGED`, `CURSOR_MISMATCH`, `TARGET_OCCLUDED`, `BUSY`, `UIA_UNAVAILABLE`, `UIA_TIMEOUT`, `CONTROL_TIMEOUT`, `CONTROL_AMBIGUOUS`, `CONTROL_SEARCH_TRUNCATED`. Для ошибок проверки цели повторите цикл снимков и наведения; для UIA уточните селектор, лимит или таймаут.

Клавиатурный ввод направляется в активное поле только выбранного окна. При необходимости активируйте это окно отдельным вызовом `--focus-only`. Без явно выбранной цели или привязанного сеанса ввод запрещён. План `--dry-run` без цели содержит `executable: false` и `TARGET_REQUIRED`; фактическое действие не выполняется.

## Краткий справочник ключей

Окна:

- `--list-windows` - вывести видимые окна Windows.
- `--active-window` - вывести текущее активное окно.
- `--window-id $windowId` - выбрать окно по `HWND`.
- `--list-controls` - вывести дочерние Win32-контролы окна.
- `--uia-list-controls` - вывести Windows UI Automation-контролы окна.
- `--uia-control-types ButtonControl,EditControl` - фильтр UIA-контролов по `ControlTypeName`.
- `--uia-highlight-automation-id num5Button` - подсветить один UIA-контрол по `AutomationId`.
- `--uia-highlight-name "Пять"` - подсветить один UIA-контрол по точному `Name`.
- `--uia-highlight-control-id 29` - подсветить один UIA-контрол по числовому `id` из текущего списка.
- `--uia-max-depth 8` - глубина обхода UIA-дерева.
- `--uia-include-offscreen` - включить UIA-контролы вне видимой области.
- `--focus-only` - только сфокусировать окно.
- `--resize-window WIDTH HEIGHT` - изменить размер окна.
- `--set-window-rect X Y WIDTH HEIGHT` - задать позицию и размер окна.
- `--minimize-window` - свернуть окно.

Индикатор и сеансы:

- `--activity-frame` / `--no-activity-frame` — включить/отключить автоматическую рамку для вызова.
- `--session-start --window-id ID` — привязать сеанс к окну и оставить рамку видимой между командами.
- `--session-end` — завершить сеанс и убрать рамку.
- `--session-status` — проверить состояние без продления сеанса.
- `--session-heartbeat` — продлить таймаут бездействия.
- `--session-timeout-s N` — таймаут бездействия при `--session-start`.
- `--session-owner-pid PID` — завершать сеанс при выходе указанного управляющего процесса.

Скриншоты:

- `--screenshot-window` - сохранить PNG окна.
- `--screenshot-after` - сделать снимок после успешного действия в том же вызове; после перемещения автоматически добавить кроссхэйр курсора.
- `--screenshot-delay-ms MS` - задержка после действия перед `--screenshot-after`; по умолчанию `screenshot_delay_ms` из настроек, 500 мс; `0` — без ожидания.
- `--screenshot-cursor-crosshair` - добавить кроссхэйр курсора; при `paired_cursor_screenshot_enabled = 1` создаёт `cursor_detail_screenshot.path`.
- `--screenshot-target X Y` - добавить красный виртуальный прицел цели без перемещения мыши.
- `--controls-overlay` - добавить рамки и ID Win32-контролов на скриншот.
- `--uia-controls-overlay` - добавить рамки и ID UI Automation-контролов на скриншот.
- `--uia-highlight-automation-id ...` - добавить зелёную рамку только выбранного UIA-контрола и красную мишень в его `click_point`.
- `--controls-limit 120` - максимум контролов для списка/overlay.
- `--controls-include-hidden` - включить скрытые контролы в список и metadata overlay.
- `--screenshot-ruler` - добавить внешнюю координатную линейку.
- `--screenshot-ruler-margin-px 48` - размер поля линейки.
- `--screenshot-ruler-step-px 50` - шаг мелких рисок.
- `--screenshot-ruler-major-step-px 50` - шаг подписей.
- `--screenshot-keep-count 10` - сколько последних скриншотов оставлять; `-1` отключает очистку.

Координаты и мышь:

- `--cursor-position` - получить текущие координаты курсора.
- `--coord-origin screen|window|client` - выбрать систему координат.
- `--mouse-move X Y` - переместить курсор в точку.
- `--mouse-move-relative DX DY` - сдвинуть курсор относительно текущей позиции.
- `--smooth-move` - включить плавное движение.
- `--click left|right` - кликнуть кнопкой мыши.
- `--scroll-ticks N` - прокрутить колесо на N тиков.
- `--scroll-direction up|down` - направление скролла.
- `--scroll-jitter` - включить дрожание курсора при скролле.

Клавиатура и текст:

- `--text "..."` - ввести текст.
- `--stdin` - взять текст из stdin.
- `--text-file PATH` - взять текст из файла.
- `--select-all` - нажать `Ctrl+A`.
- `--press-delete` или `--delete` - нажать `Delete`.
- `--press-backspace` или `--backspace` - нажать `Backspace`.
- `--press-enter` или `--enter` - нажать `Enter` отдельным действием.
- `--newline shift-enter|enter|unicode` - способ обработки переносов строк.
- `--initial-delay-s 3` - пауза перед стартом.
- `--dry-run` - получить план без изменения окон, ввода или файлов; действует для всех режимов.
- `--quiet` - не печатать подсказки в `stderr`.

## Практические правила

- Перед действием явно выбери окно или используй привязанный сеанс. Не подставляй текущее активное окно вместо закрывшейся цели.
- При `FOCUS_CHANGED`, `WINDOW_CHANGED` или `TARGET_OCCLUDED` остановись и проверь результат; не повторяй ввод автоматически. Новое диалоговое окно требует отдельного выбора.
- Для действий по скриншоту предпочитай `--coord-origin window`.
- Перед началом цикла проверки сфокусируй целевое окно через `--focus-only`.
- Если используешь `--controls-overlay`, выбирай элемент по `id/name/class_name`, затем ставь красную мишень на его `click_point`.
- Если используешь `--uia-controls-overlay`, выбирай элемент по `name/control_type/automation_id`; для Windows Calculator кнопка `5` обычно имеет `name = "Пять"` и `automation_id = "num5Button"`.
- Для финального подтверждения UIA-цели предпочитай одиночную подсветку `--uia-highlight-automation-id`, а не общий `--uia-controls-overlay`.
- При одиночной UIA-подсветке проверяй `uia_highlight_control_screenshot.path`: это чистый увеличенный снимок самого контрола без номера и мишени.
- После успешной одиночной подсветки бери координаты из `uia_control_highlight.target`; они уже сохранены как проверенная цель для следующего `--mouse-move`.
- `click_point` у Win32/UIA-контролов дан в координатах окна, поэтому перед проверкой мишени и движением мыши используй `--coord-origin window`.
- Перед реальным движением мыши можно проверить координаты через `--screenshot-target X Y`.
- Если создан `target_detail_screenshot.path`, уточняй координаты по нему: это увеличенная лупа с шагом `5 px`.
- Перед `--mouse-move` требуется снимок с `--screenshot-target X Y` или успешная одиночная подсветка UIA-контрола.
- Если создан `cursor_detail_screenshot.path`, проверяй по нему фактическую позицию курсора после перемещения.
- После `--mouse-move` следующий `--click` запрещён до снимка курсора: автоматического `--screenshot-after` или отдельного `--screenshot-window --screenshot-cursor-crosshair`. Перед кликом просмотрите полученное изображение.
- Не вычисляй цель по координатам всего PNG с линейкой: внешнее поле линейки не является частью окна. Используй числа, подписанные на линейке, и проверяй точку через красный прицел.
- Перед кликом выполни наведение и просмотри последующий проверочный снимок. `--screenshot-after` объединяет наведение и создание снимка в одном вызове.
- После клика или ввода получи финальный снимок результата через `--screenshot-after` или отдельной командой.
- Перед `Enter` всегда делай скриншот-подтверждение содержимого поля.
- Не используй `--send-enter-at-end`: этот флаг отключен, вместо него есть отдельный `--press-enter`.
- Если цель определена неточно, создайте новый снимок с мишенью и проверьте увеличенный фрагмент. Относительное перемещение `--mouse-move-relative DX DY` также требует предварительной проверки итоговой точки.
- Если окно находится на другом мониторе, экранные координаты могут быть отрицательными. Это нормально для Windows.
